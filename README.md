# Journal App

A Spring Boot REST API for managing users and their journal entries. Users are stored in MongoDB, and journal entries are linked to users through MongoDB `DBRef` references.

## Features

- Create one user or multiple users
- List all users
- Update a user by username
- Delete a user by username
- Create one journal entry for a user
- Create multiple journal entries for a user
- List a user's journal entries
- Get one journal entry by its MongoDB ObjectId
- Update or delete a user's journal entry
- Health-check endpoint

## Technology Stack

- Java 17 or newer
- Spring Boot 4.1.1
- Spring Web MVC
- Spring Data MongoDB
- MongoDB
- Lombok
- Maven

## Prerequisites

1. Install Java 17 or a newer compatible JDK.
2. Install and run MongoDB locally.
3. Make sure MongoDB is available at:

   ```text
   mongodb://localhost:27017
   ```

The application uses the `journalappdb` database by default. MongoDB collections are created when data is written.

## Configuration

Configuration is in `src/main/resources/application.properties`:

```properties
spring.application.name=journalapp
spring.mongodb.uri=mongodb://localhost:27017/journalappdb
spring.data.mongodb.auto-index-creation=true
```

Change `spring.mongodb.uri` when MongoDB is hosted elsewhere. For example:

```properties
spring.mongodb.uri=mongodb://username:password@host:27017/journalappdb
```

## Running the Application

From the project directory, run:

```bash
mvn spring-boot:run
```

On Windows, the Maven wrapper can also be used:

```powershell
.\mvnw.cmd spring-boot:run
```

The API starts at:

```text
http://localhost:8080
```

To build the project:

```bash
mvn clean package
```

To run tests:

```bash
mvn test
```

## API Overview

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/health-check` | Check whether the application is running |
| `GET` | `/api/user` | Get all users |
| `POST` | `/api/user` | Create one user |
| `POST` | `/api/user/addUser` | Create multiple users |
| `PUT` | `/api/user/{username}` | Update a user |
| `DELETE` | `/api/user/{username}` | Delete a user by username |
| `GET` | `/api/journal/{userName}` | Get all journal entries for a user |
| `GET` | `/api/journal/{userName}/{id}` | Get one journal entry |
| `POST` | `/api/journal/{userName}` | Create one journal entry |
| `POST` | `/api/journal/{userName}/addall` | Create multiple journal entries |
| `PUT` | `/api/journal/{userName}/{id}` | Update a journal entry |
| `DELETE` | `/api/journal/{userName}/{id}` | Delete a journal entry |

All endpoints use JSON request and response bodies where applicable.

## User API

### User model

```json
{
  "id": " generated by MongoDB ",
  "userName": "john",
  "passWord": "secret",
  "journalEntities": []
}
```

`userName` has a unique MongoDB index. The `id` and `journalEntities` fields are normally managed by the application.

### Create one user

```http
POST http://localhost:8080/api/user
Content-Type: application/json
```

```json
{
  "userName": "john",
  "passWord": "secret"
}
```

Returns `201 Created` with the saved user.

### Create multiple users

```http
POST http://localhost:8080/api/user/addUser
Content-Type: application/json
```

```json
[
  {
    "userName": "john",
    "passWord": "secret"
  },
  {
    "userName": "jane",
    "passWord": "another-secret"
  }
]
```

Returns `201 Created` with the saved users.

### Get all users

```http
GET http://localhost:8080/api/user
```

Returns `200 OK` with an array of users.

### Update a user

The username in the URL identifies the existing user. The request body supplies the new values.

```http
PUT http://localhost:8080/api/user/john
Content-Type: application/json
```

```json
{
  "userName": "john-updated",
  "passWord": "new-secret"
}
```

Returns `200 OK` with the updated user, or `404 Not Found` when the username does not exist.

### Delete a user by username

The repository method is `deleteByUserName`, but it is exposed through the controller as a normal HTTP route. Use the username directly in the path:

```http
DELETE http://localhost:8080/api/user/john
```

Do not call:

```text
/api/user/deleteUserByUserName/john
```

Returns `204 No Content` when the user is deleted, `404 Not Found` when the user does not exist, or `400 Bad Request` when the delete operation fails.

If a username contains spaces or special characters, URL-encode it before placing it in the path.

## Journal API

### Journal model

```json
{
  "id": " generated by MongoDB ",
  "title": "A first entry",
  "content": "Today I started using the journal app."
}
```

Journal entries are stored in the `journal_entries` collection. The user's `journalEntities` list stores references to the user's entries.

### Get all journal entries for a user

```http
GET http://localhost:8080/api/journal/john
```

Returns `200 OK` with the user's journal entries. If the user does not exist, it returns `404 Not Found` with `USER NOT FOUND`.

### Create one journal entry

```http
POST http://localhost:8080/api/journal/john
Content-Type: application/json
```

```json
{
  "title": "A first entry",
  "content": "Today I started using the journal app."
}
```

Returns `201 Created` when the entry is saved and linked to the user.

### Create multiple journal entries

```http
POST http://localhost:8080/api/journal/john/addall
Content-Type: application/json
```

```json
[
  {
    "title": "Morning",
    "content": "Started the day early."
  },
  {
    "title": "Evening",
    "content": "Finished the first feature."
  }
]
```

Returns `201 Created` when the entries are saved and linked to the user.

### Get one journal entry

Replace the id with the entry's 24-character MongoDB ObjectId.

```http
GET http://localhost:8080/api/journal/john/507f1f77bcf86cd799439011
```

Returns `200 OK`, or `404 Not Found` when the user or entry does not exist.

### Update a journal entry

```http
PUT http://localhost:8080/api/journal/john/507f1f77bcf86cd799439011
Content-Type: application/json
```

```json
{
  "title": "Updated title",
  "content": "Updated content."
}
```

Returns `201 Created` after the entry is updated. It returns `404 Not Found` when the user or entry does not exist.

### Delete a journal entry

```http
DELETE http://localhost:8080/api/journal/john/507f1f77bcf86cd799439011
```

Returns `204 No Content` after the entry is deleted and removed from the user's journal references. It returns `404 Not Found` when the user or entry does not exist.

## Example curl Commands

Create a user:

```bash
curl -X POST http://localhost:8080/api/user ^
  -H "Content-Type: application/json" ^
  -d "{\"userName\":\"john\",\"passWord\":\"secret\"}"
```

Create a journal entry:

```bash
curl -X POST http://localhost:8080/api/journal/john ^
  -H "Content-Type: application/json" ^
  -d "{\"title\":\"First entry\",\"content\":\"Hello journal\"}"
```

Delete a user:

```bash
curl -X DELETE http://localhost:8080/api/user/john
```

The examples above use Windows `cmd.exe` line-continuation characters. In PowerShell, put each command on one line or use the PowerShell backtick for line continuation.

## Data Model

- `UserEntity` is stored in the `user_entity` collection.
- `JournalEntity` is stored in the `journal_entries` collection.
- Each user contains a list of `DBRef` references to journal entries.
- `userName` is unique through a MongoDB index.
- MongoDB generates `ObjectId` values for users and journal entries.

## Troubleshooting

### A request returns 404

Check all of the following:

1. Confirm the HTTP method is correct. Delete routes require `DELETE`, not `GET`.
2. For user deletion, use `/api/user/{username}`.
3. For journal routes, include the username: `/api/journal/{userName}`.
4. For entry-specific routes, use a valid 24-character MongoDB ObjectId.
5. Restart the application after changing controller or repository code.
6. Confirm the application is running on port `8080`.

### MongoDB connection errors

Confirm that MongoDB is running and that the configured URI is reachable:

```text
mongodb://localhost:27017/journalappdb
```

### Duplicate username errors

`userName` is unique. Creating another user with the same username can fail because MongoDB enforces the unique index when auto-index creation is enabled.

## Current Limitations

- There is no authentication or authorization layer.
- Passwords are stored as ordinary fields and are not hashed.
- There is no global exception handler or formal API error schema.
- User deletion does not explicitly delete the journal documents referenced by that user.
- The API currently returns some different status codes for similar operations, such as `201 Created` for journal updates.
